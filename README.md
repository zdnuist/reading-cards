# 流动的书 · 阅读复习助手

把你在微信读书里读过的书、划过的线，变成每天重新经过你一次的卡片。
解决的核心问题不是"读得太少"，而是**读过就忘**——所以除了回顾，它还内置了间隔复习调度。

## 快速开始

```bash
cd reading-cards
export WEREAD_API_KEY=wrk-xxxxxxxx      # 微信读书 API Key（Agent API Gateway）
npm start                                # 或：node --experimental-sqlite server.js
# 打开 http://localhost:4321
```

首次使用：点右上角「同步微信读书」，后台拉取书架 + 全部有笔记的书（约 14 秒）。
也可以用命令行同步：`node --experimental-sqlite sync.js`（可选参数：限制本数、`noshelf` 跳过书架）。

### 没有配置 `WEREAD_API_KEY` 时

页面**照常打开、不报错**，只是没有书和划线：

| 位置 | 表现 |
|---|---|
| 顶部 | 出现琥珀色提示条，给出 `export WEREAD_API_KEY=...` 与重启命令 |
| 统计 | 连续天数 / 卡片总数 / 收藏 / 待复习 全是 0 |
| 今日 | 显示「还没有卡片 · 配置好 API Key 之后，这里会出现每天回顾的卡片」，不出现同步按钮，「换一批」置灰 |
| 卡片库 / 主题 / 书架 | 各自的空态文案 |
| 成长看板 | 全 0，「还没有复习记录」引导 |
| 点「同步微信读书」 | 约 170ms 内返回，提示条变成报错态并附上配置命令 |

Key **无效或过期**（已配置但值不对）时行为不同：`keyConfigured` 仍为 true（服务端无法预判有效性），
点同步后约 0.6 秒失败，提示条显示「同步失败：微信读书鉴权失败：API Key 无效或已过期」。

## 数据备份

你写的感悟、收藏、复习记录**只存在 `data/reading.db` 一个文件里**，所以必须有备份。

- **自动**：服务每天首次启动时备份一次（`autoBackup()`），保留最近 7 份
- **手动**：右上角「备份」按钮，或「成长 → 数据备份」
- **机制**：SQLite `VACUUM INTO`，可在数据库正被读写时执行，得到一致性快照，
  且比原库更小（实测 2.1 MB → 1.9 MB）
- **位置**：`data/backups/reading-YYYY-MM-DD.db`

已验证可恢复：备份与源库逐表行数一致，`PRAGMA integrity_check` 为 `ok`。

> 备份在同一块盘上，机器挂了会一起没。生产部署请把 `data/backups/` 同步到异地，
> 见 [DEPLOY.md](DEPLOY.md)。

**导出**：`GET /api/export` 只导出你自己写的数据（感悟/收藏/点赞/复习状态 + 被引用的划线原文），
不含 4000 条可从微信读书重新同步的划线。带 `format: liudongdeshu.userdata.v1` 版本号，便于迁移。

## 云端部署

见 **[DEPLOY.md](DEPLOY.md)**。核心结论：微信读书网关只允许 `weread.qq.com` 这一个 Origin
调用（实测 `access-control-allow-origin` 是固定值），所以 Key 只能在服务端使用，
「纯前端 + 云数据库」的多用户架构不可行。

## 每日复习提醒

已配置每天 **21:00** 的自动化任务，推送当天到期的复习卡片。

`remind.py` 直接以**只读**方式打开 `data/reading.db`，不依赖服务是否启动——
自动化跑的时候服务未必开着，走 HTTP 接口会失败。

```bash
python3 remind.py     # 输出当天到期卡片 / 统计 / 连续天数
```

- 有到期卡片：列出最多 3 条原文 + 书名 + 上次复习时间
- 没有到期卡片：从「从未复习过」的卡片里随机推荐 3 张，避免提醒变成空转

## 技术选型

| 层 | 方案 | 理由 |
|---|---|---|
| 运行时 | Node.js 22 内置 `node:sqlite` | 零第三方依赖，真正的本地数据库文件 |
| 存储 | SQLite（`data/reading.db`，WAL） | 数据完全在本地，可备份、可迁移 |
| 服务 | Node 内置 `node:http` | 无框架依赖，启动即跑 |
| 前端 | 原生 HTML/CSS/JS | 翻卡交互用 CSS 3D transform，无需构建 |

## 错误处理约定

- `call()` **先解析 body 再判状态码**：微信读书网关的鉴权失败可能是 `HTTP 401 + errcode -2013`，
  也可能是 `HTTP 200 + errcode≠0`，两种都要覆盖，否则会把鉴权失败当成「没有数据」而静默成功。
- 配置类 / 鉴权类错误标记为 `fatal`，**不重试**（原来会白等 2.8 秒重试 3 次）。
- **`syncState` 里不能有名为 `error` 的字段**：前端 `api()` 把任何 `error` 字段当作请求失败抛出，
  会让轮询回调每次抛异常、定时器永不清除，同步失败时界面卡在「同步中」。对外改名为 `syncError`。

## 数据来源

全部来自微信读书官方 Agent API Gateway（`https://i.weread.qq.com/api/agent/gateway`）：

- `/shelf/sync` → 书架书籍
- `/user/notebooks`（游标分页）→ 有笔记的书
- `/book/bookmarklist` → 每本书的划线原文
- `/review/list/mine` → 每本书的想法与点评

当前库内实测：920 本书、4083 条划线、165 条想法、4004 张可用卡片。

## 核心机制

**瀑布流布局**：卡片高度由句子长短自然决定（最短 300px，长段落最高约 600px，超出部分卡内滚动）。
实现方式是 `grid-auto-rows:2px` + JS 按 `offsetHeight` 换算每张卡的 `grid-row-end: span N`，
配合 `grid-auto-flow:row dense` 回填空洞，保证三列间距恒定 18px、无空档。

关键约束：**正面撑开高度，背面绝对定位覆盖**。这样翻面时卡片高度不变，瀑布流不会因为翻卡而跳动；
背面内容超出可视高度时在卡内滚动，并给底部加渐隐提示。

**每日推荐**：用日期字符串做种子做确定性洗牌，当天稳定、跨天自动换新；优先插入到期复习的卡片。

**间隔复习**：简化 SM-2。三档反馈对应间隔 1/2/4/7/15/30/60 天——
- 忘了 → 重置到 stage 0，明天再见到它
- 记得 → 升一级
- 简单 → 升两级

**成长看板**：区分两个容易混淆的指标——
- **首回忆成功率** = 每张卡片第一次被回忆时答对的占比。它回答的是「读完合上书，你还剩多少」，是最诚实的指标。
- **答对率** = 全部复习事件的答对占比。它会被反复复习的卡片稀释，不能单独看。
- 卡片成熟度按 stage 展示下次间隔；标尺只按「已复习卡片」的量级算，否则未复习的 4000 张会把所有条压成 0。

**卡片成图**：Canvas 手绘 1080×1350 海报（导出 2160×2700 PNG），按篇幅自适应字号、
CJK/西文分词换行、避头尾处理、正文垂直居中；有感悟时自动加感悟块。全程无第三方依赖。

**主题聚类（本地轻量，无 API、无模型）**：`topics.js`
- 分词：CJK 二元组 + 拉丁词，不依赖词典；用助词表 + 文档频次（DF 3‰~5%）双重去噪
- 向量：TF-IDF + L2 归一化
- 聚类：球形 KMeans（k-means++ 初始化、余弦相似度、`k ≈ N/160` 上限 24），
  固定种子（`hashSeed('topics::N')`）保证重建结果可复现。4004 张卡片约 1.1 秒
- 命名：直接抽**2~4 字词**并按「长词优先」剪枝，才能得到「指数基金」「机器学习」这种完整词，
  而不是被切碎的「数基」「器学」。剪枝规则两条：
  1. 长词 G 的频次 ≥ 子串频次 × 0.75 时，子串判为碎片丢弃
  2. 被虚词判定剔除的长词（如「为什么」含「什么」），它切出的碎片（「为什」）一并丢弃
- 停词表分两层：`STOP_FUNC`（虚词/句式碎片，可做长词子串判定）与
  `STOP_GENERIC`（泛化名词，**只对二元组本身生效**）。若把「问题」放进前者，
  「解决问题」会因包含它被整条剔除，反而让碎片「解决问」留下来

## 功能清单

- 今日卡片（6 张，确定性生成）+ 换一批
- 点击翻面：书籍详情（封面/作者/分类/进度/章节/划线时间/原书链接）+ 当时在微信读书的想法
- 在卡片背面写「现在的感悟」与「行动结果」，可删除
- 同感（点赞）/ 收藏（弹窗记录当下想法 + 时间）
- 收藏夹：按时间倒序，展示收藏瞬间的感悟
- 我的感悟：按日聚合的时间线，支持导出 Markdown
- 卡片库：搜索句子/书名/作者，按书筛选，只看收藏
- 书架：查看书籍与卡片数，手动新增非微信读书的书
- 连续打卡天数统计
- 成长看板：首回忆成功率、已复习覆盖、真正记住的卡片数、待复习、每日复习量堆叠柱、卡片成熟度分布、复习最多的书
- 卡片成图：把句子 + 出处 + 你的感悟导出成分享海报
- 主题：24 个语义聚类的主题，显示跨书覆盖（几张卡片 / 几本书），点进去看该主题下全部卡片；卡片背面带主题标签可一键跳转
