# 「流动的书」技术报告

> 把读过的书真正内化进生活 —— 一条从"划线"到"行动"的智能复习闭环。
> WorkBuddy「1024 造物挑战」程序员节应用创作大赛 · 作品提交

---

## 一、问题与动机

微信读书等阅读 App 沉淀了海量划线与想法，但它们普遍存在三个断层：

1. **划线即沉睡**：划完即沉底，再没被翻开过第二次，"收藏 = 学会"是幻觉。
2. **缺少复习机制**：没有基于遗忘曲线的智能排期，读过就忘。
3. **缺少内化引导**：读者不知道如何把一句话与自己的经验、其他书、实际行动连起来。

「流动的书」要做的，是把静态划线变成**会流动、会重逢**的复习卡片，并用 AI 帮用户把每一句话**真正读懂**。

## 二、核心方案

一条被学习科学验证的闭环：

```
划线 ──▶ 智能排期复习 ──▶ AI 解读内化 ──▶ 写下感悟与行动
（汇聚）   （遗忘曲线）      （解读/联想/追问）   （知识落地）
```

- **每日精选**：每天 0 点自动换新 6 张卡片 + AI 每日导语。
- **翻卡复习**：正面划线原文，背面"当时的想法 / 现在的感悟 / 行动结果"；三档反馈（忘了/记得/简单）驱动遗忘曲线安排下次复习。
- **AI 解读**：对划线生成「解读 / 跨书联想 / 苏格拉底式追问」。
- **主题聚类**：不同书的划线聚成主题网络，看"同一件事不同作者怎么说"。
- **学习仪表盘**：连续天数、待复习、感悟/行动分布与趋势。

## 三、系统架构

见 `architecture.svg`。要点：

- **入口层**：Caddy 反向代理（`:8899`），承接公网访问。
- **服务层**：Node.js 服务，**零第三方依赖**，仅用内置模块 `node:http` + `node:sqlite` + `node:crypto`，前端原生 HTML/CSS/JS。
- **身份层**：`resolveIdentity` 中间件统一识别身份——
  - 管理员：站点口令登录，种 HMAC 签名的 `owner_session` Cookie，uid = `owner`；
  - 访客：免密默认进入，Cookie 随机 UUID 生成 uid = `guest:<uuid>`。
- **数据层**：SQLite（`data/reading.db`），**共享数据与隔离数据分层**——
  - 共享：`books / highlights / topics / daily_pick`（所有人看同一份书库）；
  - 按 `user_id` 隔离：`insights / likes / favorites / reviews / review_log / checkin`（每人独立）。
- **后台服务**：微信读书网关同步（仅管理员）、AI 解读层、自动备份。

## 四、关键工程实现

1. **多用户隔离模型**：共享数据 + 按 user_id 隔离的交互数据。数据库通过幂等迁移平滑升级：`ALTER TABLE ADD COLUMN` 与"重建表并入 user_id 主键"双路径，旧数据安全归入 `owner`。
2. **应用内鉴权**：鉴权从代理层下沉到应用内。口令用 `crypto.timingSafeEqual` 防时序攻击；会话用 `crypto.createHmac(SESSION_SECRET)` 签名；写操作（同步/备份/导出/聚类/增书）由 `requireOwner` 在服务端强制拦截，不依赖前端隐藏按钮。
3. **AI 可插拔层（`ai.js`，已上线）**：
   - 线上由 **Qwen 大模型（SiliconFlow，OpenAI 兼容端点）** 实时驱动，对划线生成「解读 / 跨书联想 / 苏格拉底追问」，约 4–5 秒返回（真实示例见一页纸）；
   - 针对推理模型默认关闭思考模式（`enable_thinking:false`），避免超长思维链导致超时回退；
   - 未配置或调用失败，自动回退**内置模板引擎**，保证离线 / 演示环境永远可用、输出稳定；
   - 结果按 `模式+文本哈希` 缓存于 `ai_cache` 表，避免重复调用、降低成本；
   - 任意 OpenAI 兼容端点（通义 / DeepSeek / OpenAI…）均可切换，改 `.env` 即换模型。
4. **遗忘曲线排期**：基于反馈质量（0/1/2）计算下次复习间隔，生成每日待复习卡片池，并统计连续打卡天数。
5. **卡片成图分享**：用 Canvas 手绘 1080×1350 海报（含 CJK 分词换行、避头尾处理），无第三方依赖导出 PNG。

## 五、访客模式（现场演示友好）

为竞赛现场多人体验设计：评委/朋友打开链接**默认即访客**，可浏览主人配置的书库、写自己的感悟与收藏——**彼此隔离，也看不到主人的数据**。这让一台服务、一个链接，就能让多人同时安全体验，是个人项目里少有的"多人可玩"属性。

## 六、部署与运维

- 腾讯云 Lighthouse + systemd（`reading-cards.service`）+ Caddy 反代。
- `.env` 注入密钥（`WEREAD_API_KEY / SITE_PASSWORD / SESSION_SECRET`，权限 600，不入库）。
- 代码经 GitHub 版本管理，服务器 `git pull` + 重启完成更新。
- 自动备份 `data/backups`（保留最近 7 份），支持一键导出用户数据。

## 七、数据合规说明

书籍与划线数据来源于**用户本人微信读书账号的授权导出**，用于个人学习复盘；应用同时支持手动粘贴导入作为兜底。所有交互数据为用户私有，管理员仅管理自己的数据。

## 八、差异化与创新点

- **本土数据源闭环**：直接打通微信读书划线，把"读"和"复习"接上。
- **AI 内化而非仅收藏**：实时大模型输出「解读 / 跨书联想 / 追问」三层，逼读者从"收藏"走向"思考"。
- **零依赖 + 数据分层隔离**：工程上极简、安全，又天然支持多用户。
- **演示友好**：访客免密 + 每人隔离，一台服务即可多人现场体验。
